# v0.10.0 — Bot tactics, navigation and customization

Version 0.10.0 is a major update to Bot map tactics, route editing, movement and combat behavior. Attack routes across all 41 supported maps have been comprehensively revised, substantially improving Bot movement and tactical deployment. The revised routes, waiting places and artillery positions now form the default configuration used by new profiles and restoration commands.

The supported game client remains **Chinese HD World of Tanks 0.9.22.0.1 #1513**. The project version does not change the required game client.

## Bot routes and map tactics editor

- Open and edit default routes directly: move, insert or delete waypoints; rename, duplicate or delete routes; and restore individual routes or the complete default profile.
- The default **Total routes** view displays all vehicle-class routes and artillery positions together. Light tanks use green, medium tanks yellow, heavy tanks gray, tank destroyers blue and artillery positions red. The shared **All vehicle classes** editing template uses black.
- Configure routes independently for light tanks, medium tanks, heavy tanks and tank destroyers. Editing the shared template updates its class variants and removes their independent waiting settings; subsequently editing a class variant makes that class's geometry take precedence. The shared template itself has no waiting places.
- Set route and artillery-position priorities from 0 to 9, with 5 as the default. Higher-priority usable choices are allocated first; choices of equal priority are randomized. Route capacity is calculated separately for each team and vehicle class, with up to three vehicles per class route. Exhausted or unavailable choices fall back to automatic navigation.
- Corresponding symmetric routes use matching random choices when both sides' availability and capacity allow it. Independent, asymmetric routes are allocated independently.
- Route symmetry synchronizes the same coordinates in reverse order. Maps with separate spawn and capture areas default to symmetry off, while still allowing it to be enabled and saved manually.
- Display spawn centers separately from capture bases. A one-shot command moves a selected route's endpoints to the two spawn centers.
- Improve route selection, editing legends, undo/redo, import/export, map names and bilingual built-in route/position labels. Existing saved profiles are retained when upgrading.

## Independent waiting places

- Each ordinary waypoint can have up to three independent small waiting places. Each place holds one vehicle and has its own waiting duration and preferred initial heading.
- Waiting defaults to **60 seconds** and starts after arrival. A duration of -1 has no timed departure. A blank heading prefers the next waypoint; subsequent combat can freely turn the hull and turret.
- Waiting vehicles continue acquiring targets, aiming and firing. Waiting restricts travel rather than locking hull rotation, which is particularly important for vehicles without turrets.
- Show a **6 m radius large-vehicle clearance guide** around waiting places while editing. Selected groups expand to show their individual places and headings; unselected groups retain a compact waypoint marker.
- Occupied or unusable places are avoided in favor of another usable place in the same group. If none is available, the vehicle follows the ordinary waypoint without waiting or forming a queue.
- Deleting the final small place completely removes the waypoint's waiting state. Fix residual waiting durations, reappearing deleted places and unintended inheritance of waiting settings.
- Map checks include individual waiting places and their entry/exit connections, with specific locations in the results.

## Bot navigation and avoidance

- Improve ascent and descent navigation, heading stability, local targets and continuation along authored routes. Reduce unnecessary circling, repeated reverse turns and excessive slope avoidance on passable terrain.
- Improve recovery from nearby vehicles, side contacts and wrecks. Bots attempt local avoidance, bounded pushing where appropriate and alternative routes when progress remains blocked.
- Ordinary blocked waypoints have a bounded attempt period. Bots can abandon an unreachable waypoint and attempt its successor; repeated failure can trigger a route change instead of indefinitely returning to the blocked location.
- Correct private-route search origins, consumed fallback anchors, stale recovery state and cyclic reentry targets. Improve continuation after leaving an eroded navigation cell.
- Use full throttle for ordinary movement and recovery maneuvers. Friendly yielding and contact-related give-way maneuvers use reduced throttle to limit congestion.
- Improve late-battle route continuation, recovery after target loss and movement toward objectives. Revise spawn deployment and handling of destroyed destructible obstacles.

## Bot combat and artillery

- Align armored and lightly armored tank destroyers with the sniper role, improving their use of authored waiting positions.
- Improve fixed-gun hull alignment and recovery from restricted firing angles. Bots can adjust their firing position instead of remaining exposed while unable to aim.
- Improve snap-shot readiness checks so firing respects the actual gun's alignment. Difficulty-dependent reaction, aiming patience and prediction errors remain effective.
- Improve long-range artillery aiming, trajectory evaluation and firing recovery. Persistent inability to obtain a usable shot can prompt a change of parking position or artillery zone.
- Artillery uses stationary deployment zones rather than ordinary attack routes or timed movement points. Default positions are editable and removable. Their default 16 m radius defines a parking search region, not a vehicle-size clearance circle or unrestricted roaming area.

## Appearance, style inventory and shop

- Restore customization prices and purchase behavior using the supported client's catalog and transaction rules, replacing unconditional zero-price behavior.
- Add preset-style categories to the warehouse and shop. The warehouse lists owned styles; the shop offers styles permitted for purchase by the catalog.
- Add a **Styles** page to the launcher's custom-save editor, between Garage vehicles and Personal missions. It includes hidden preset styles, stock editing and explicit applicability information.
- Allow adding individual style copies instead of always adding enough copies for every compatible vehicle. Retain an explicit option for filling stock for compatible vehicles.
- Distinguish similarly named national styles and list complete supported vehicle ranges and exclusions.
- Provide sufficient style inventory in the fully unlocked default save for compatible vehicles.
- Fix style removal, inventory display, missing glyphs and related shop/warehouse integration problems.
- Add in-game system notifications for custom-save changes to styles, garage vehicles, currencies, free experience, bonds and reward multipliers.

## Gameplay and reliability fixes

- Fix prolonged Bot stalls during route and capture travel: bounded retries now skip failed waypoints, rejoin alternative routes from the current position, and allow selected artillery capturers to advance when only artillery Bots remain.
- Correct Bot-to-player ram damage handling and contact deduplication.
- Improve drive/steering power allocation and bounded handling of vehicle launch, suspension overlap and terrain sinking cases.
- Improve destructible-object handling at spawn, including vehicles starting on fragile objects. Correct multi-stage vehicle-crush handling for Prague factory gates and initialization of small destructible vegetation.
- Correct penetration feedback for internal-module damage and destruction. Clear fire, extinguishing and repair indicators when a vehicle is destroyed.
- Fix a battle-runtime diagnostic error that could terminate a battle with a system-error message.
- Raise the supported Bot configuration document size to 8 MB and improve configuration persistence, default restoration and label display.

## Validation and downloads

GitHub validation is updated for the current configuration baseline, editor behavior and package contents. Client executable bytecode is checked against the release checkout rather than the frozen 0.9.7 code inventory. The Windows distribution is built from the release's main commit and checked for x64 launcher architecture, embedded client version, source consistency and bundled runtime behavior.

Automated tests and package checks do not substitute for native game testing. Remaining navigation/physics regression failures remain visible in CI rather than being removed to obtain a green result.

Release assets:

- **Windows-x64.zip**: the runnable launcher distribution; extract once and run the launcher.
- **Source-and-validation.zip**: matching source and validation tools.
- **Bot-Editor-Guide-English.md**: a separate English guide covering routes, priorities, symmetry, waiting places, artillery positions and saving/restoration.
