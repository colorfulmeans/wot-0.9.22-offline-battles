# 诊断入口与错误报告提交说明

适用版本：1.0.0；支持客户端：中国区高清版《坦克世界》0.9.22.0.1 #1513。

## 一、入口用途

完整解压启动器包，保留EXE、_internal及所有随包文件。切换入口前退出游戏和启动器，避免仍在旧会话中测试。

| 文件名 | 用途 |
| --- | --- |
| wot-0.9.22-offline-battles.exe | 日常游戏，保留必要关键记录 |
| START_DIAGNOSTIC_TEST.bat | 详细对局诊断，复现导航、交战、模块、声音和模型等问题时优先用 |
| START_SPIKE_PROFILE.bat | 额外性能分析，适合开销和帧时间尖峰调查 |
| START_ROOF_CRUSH_TEST.bat | 胜利之门桥上推车跌落专用测试 |
| START_ROOF_SHOT_DROP_TEST.bat | 胜利之门桥下射击触发落车专用测试 |

桥上推车入口中，玩家在桥上，友军车辆沿桥边停放，可推动车辆落下测试首次冲击、落地、持续压车和残骸接触。射击触发落车入口中，玩家在桥下，每次成功射击释放一辆桥上BOT，便于重复观察落到车顶的效果。专用测试中BOT不主动开火。

两个落车入口不替换正常房间的保存阵容。测试完退出，再从正常或诊断入口启动所需对局。

## 二、复现和生成报告

1. 用START_DIAGNOSTIC_TEST.bat打开当前测试包。
2. 确认存档、车辆属性方案、BOT配置、阵容、地图、难度和等级范围。
3. 开始对局并复现；记下车辆、位置、时间及是否有玩家操作。
4. 对局或测试会话结束后，回启动器点击“一键汇报错误…”。
5. 保存生成的wot-error-report-日期-时间-会话标识.zip，提交这个完整ZIP。

报告通常位于当前Windows用户的LocalAppData/WoTOfflineBattles/reports。启动器按本次会话的日志起止位置收集，不是把整个历史python.log混在一起。一个启动会话可含多局，因此需说明问题出在哪一局。

报告目录默认仅保留最新3份完成报告。重要复现请及时复制到其他位置并改成可区分名称；恢复出厂会清项目报告目录，手动复制出去的文件不在清理范围。

## 三、报告包含什么

报告按可获得情况收集启动器、服务端、可见玩家客户端、隐藏模拟客户端及隐藏客户端启动日志，还可包含环境摘要、音频分析及已经生成的崩溃转储。

缺少某一来源时应查看报告中的缺失说明，不能仅因有一个ZIP就认定所有链路齐全。正常退出、玩家主动关闭、启动器清理隐藏进程与原生崩溃是不同事件。

详细诊断有输出预算和重复抑制，预算达到上限会有提示；错误和生命周期消息继续保留。日志多、开局负载高、网络ping高和画面帧率低也不是同一个指标。

## 四、按问题提供补充信息

| 问题 | 请附的信息 |
| --- | --- |
| 路线受阻／绕行 | 地图、队伍、车型、路线名、点号、车辆名、附近尸体或障碍、最终是否脱困 |
| 火炮不开炮／摆动车身 | 火炮型号、距离、目标是否点亮、坡地位置、是否有炮位、弹药配置和发生时间 |
| 无弹后不行动 | 是全0初始配置还是打空、其他弹种是否有库存、是否仍装填、当前路线与位置 |
| 声音问题 | 进入战斗／返回车库／切图哪一步、错误文字、音乐或音效具体表现 |
| 模型断言／闪退 | 错误窗口、发生时机、是否自行退出、是否产生转储 |
| 性能问题 | 地图、人数、开局或中后期、画面FPS和ping、普通还是诊断入口 |
| 友军击毁／蓝名 | 攻击者与受害者队伍及身份、炮击／溅射／碰撞等来源、自己看到的是友军还是敌军颜色 |

截图用于定位，完整报告用于追踪原因。请保留发生问题前后的过程；一时停车后成功脱困，与持续卡到终局需要分别描述。

## 五、崩溃转储

启动器的崩溃收集设置可使用Microsoft ProcDump；相关下载遵循启动器现有设置。完整内存转储可能很大，并非每次生成错误报告都会自动得到完整转储。

原生异常需要同版本程序、日志和对应转储配套分析。仅靠日志最后一行或“进程退出”不能确定崩溃根因。不要在已经结束的会话之后开启转储，再期待补回之前的故障现场。
